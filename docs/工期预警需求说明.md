# 工期预警需求说明文档

## 1. 需求概述

### 1.1 需求背景
在铁路工程项目施工过程中，由于施工环境复杂、任务量大、周期长，工期管理是项目管理的核心环节。为了确保项目按时交付，需要建立一套完善的工期预警机制，对施工进度进行实时监控，及时发现并预警潜在的工期风险。

### 1.2 需求目标
- 实现施工阶段和WBS层级的工期预警监控
- 支持多种预警类型（未按期开工、临期未完成、已延期）
- 提供预警详情查看和处理功能
- 支持大屏展示预警信息
- 实现预警数据的统计分析

## 3. 数据模型

### 3.1 施工阶段预警数据
```typescript
interface StageWarning {
  id: string;           // 预警ID
  code: string;         // 预警编号
  stageName: string;    // 阶段名称
  planStart: string;    // 计划开始时间
  planEnd: string;      // 计划完成时间
  status: string;       // 当前状态
  warnType: string;     // 预警类型
  warnEnabled: boolean; // 是否启动预警
  bigscreen: boolean;   // 是否大屏展示
}
```

### 3.2 WBS工期预警数据
```typescript
interface WbsWarning {
  id: string;           // 预警ID
  code: string;         // 预警编号
  target: string;       // 预警对象
  nodeType: string;     // 节点类型
  unit: string;         // 单位工程
  dept: string;         // 分部工程
  item: string;         // 分项工程
  relativePath: string; // 层级路径
  planStart: string;    // 计划开始时间
  planEnd: string;      // 计划完成时间
  progress: number;     // 当前进度(%)
  completedCount: number; // 已完成构件数
  totalCount: number;   // 关联构件总数
  status: string;       // 当前状态
  warnType: string;     // 预警类型
  level: string;        // 预警等级
  timeInfo: string;     // 时间信息
  owner: string;        // 负责人
  handleStatus: string; // 处理状态
  warnTime: string;     // 预警生成时间
  reason: string;       // 判断依据
  warnEnabled: boolean; // 是否启动预警
  bigscreen: boolean;   // 是否大屏展示
}
```

## 4. 非功能需求

### 4.1 性能需求
- 预警列表加载时间 ≤ 2秒
- 预警详情加载时间 ≤ 1秒
- 支持至少1000条预警数据的展示

### 4.2 可用性需求
- 预警信息实时更新，支持自动刷新
- 预警等级颜色区分明显，便于快速识别
- 支持键盘操作（Tab切换、Enter确认等）

### 4.3 安全性需求
- 预警处理操作需记录操作日志
- 敏感预警信息（如重大预警）需权限控制
